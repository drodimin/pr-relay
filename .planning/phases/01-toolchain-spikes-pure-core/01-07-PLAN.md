<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Executor → GitHub (two identities) | Commands run as drodimin and as a second account via per-command GH_TOKEN |
| Dummy repo → public pr-relay repo | Captured JSON is committed publicly |
| actor.yml → GITHUB_TOKEN | The workflow writes to PRs in the dummy repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-29 | Information Disclosure | second-account token | mitigate | Read via `gh auth token --user` inline in the command env only. Never echoed, logged, written to a file or committed. Plan acceptance greps the commit for "gho_" / "ghp_" prefixes: `git log -p -1 | grep -E 'gh[op]_[A-Za-z0-9]{20}'` must be empty |
| T-01-30 | Elevation of Privilege | wrong-repo writes (scenario commands hitting drodimin/pr-relay) | mitigate | All gh commands pass `-R D` or a repos/D path. The capture.sh PR_RELAY_FIXTURE_REPO guard. Git operations run in a clone outside the pr-relay worktree |
| T-01-31 | Information Disclosure | fixture bodies in public repo | mitigate | capture.sh sentinel replacement. TestDecodeAllFixtures asserts only ""/sentinel bodies remain. Fixture bodies are "# pr-relay fixture" anyway |
| T-01-32 | Elevation of Privilege | actor.yml permissions | mitigate | Least privilege `pull-requests: write, contents: read`. workflow_dispatch only (no pull_request_target). Lives only in the dummy repo |
| T-01-33 | Tampering | synthetic fixtures mistaken for real behaviour | mitigate | `synthetic-` directory prefix plus a `_synthetic` key describing the mutation |
</threat_model>
